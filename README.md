# nginx_updater

Обновление nginx одной командой — скрипт определяет, работает ли сервер через системную службу (APT) или Docker Compose, и выбирает подходящий способ. Для APT он использует nginx.org; для Docker — официальный Alpine-образ nginx. Перед заменой проверяет конфигурацию и создаёт резервную копию. Интерфейс и сообщения на русском.

## Быстрый запуск

На сервере с Ubuntu или Debian:

~~~sh
curl -fL --retry 3 -o nginx-updater.sh \
  https://raw.githubusercontent.com/Daniil-GR/nginx_updater/main/nginx-updater.sh
sh -n nginx-updater.sh
sudo sh nginx-updater.sh
~~~

**По умолчанию (`--auto`) скрипт сам определяет рабочий nginx.** Если используется системный пакет — обновляет его через APT, сохраняя текущую ветку nginx.org (либо выбирая stable). Если работает единственный nginx в Docker Compose — обновляет его официальный Alpine-образ, даже когда на сервере дополнительно установлен, но остановлен системный nginx. При неоднозначности (несколько контейнеров, одновременно активный системный nginx и Docker, неизвестный способ запуска) ничего не меняет и предлагает выбрать цель вручную. `--auto` не устанавливает новый nginx, если обновлять нечего.

Для интерактивного меню:

~~~sh
sudo sh nginx-updater.sh --menu
~~~

## Команды

| Команда | Назначение |
| --- | --- |
| --auto | Автоматически определить рабочий nginx и обновить через APT или Docker (по умолчанию) |
| --system-update | Обновить только работающий системный nginx через APT, сохраняя ветку nginx.org; если ветка не настроена — stable |
| --stable | Обновить только системный nginx из nginx.org stable |
| --mainline | Обновить системный nginx до mainline |
| --install | Впервые установить системный nginx stable (без автозапуска) |
| --docker-status | Посмотреть контейнеры nginx, версии образов и метки Compose |
| --docker-update NAME [IMAGE] | Обновить конкретный nginx-контейнер Compose до последней `stable-alpine` или до заданного `nginx:X.Y.Z-alpine` |
| --menu | Консольное меню управления |
| --status | Посмотреть версию, источник APT, статус nginx |
| --check | Обновить APT-индексы, посмотреть доступные версии |
| --test | Запустить nginx -t и показать загруженные конфиги |
| --diagnose | Посмотреть HTTP/2, динамические модули и слушающие порты |
| --backup | Сделать резервную копию nginx |
| --help | Помощь |

## Что делает автоматическое обновление

1. Проверяет, как запущен nginx: из системной службы или в Docker. При единственном обнаруженном Docker-nginx обновляет его, даже если на хосте есть отключённый APT nginx. При нескольких активных вариантах или неизвестной сборке останавливается без изменений и позволяет обновлять экземпляры по отдельности.
2. Для выбранного способа проверяет текущую конфигурацию (`nginx -t`).
3. Для APT проверяет совместимость модулей, пакетов и портов; для Docker — целевой Compose-сервис, образ и структуру файлов.
4. Сохраняет конфигурацию: `/etc/nginx` при APT либо Compose-проект и `docker inspect` при Docker в `/var/backups/nginx-updater/`.
5. Для APT подключает nginx.org с проверкой GPG-ключа; для Docker скачивает официальный Alpine-образ.
6. Сравнивает версии и не понижает nginx автоматически.
7. Для APT выполняет симуляцию установки и блокирует удаление посторонних пакетов; для Docker проверяет новый образ в одноразовом контейнере.
8. Обновляет выбранный экземпляр: APT-пакет либо один Compose-сервис. Другие контейнеры и `rw-core` не пересоздаются.
9. Проверяет работу nginx после установки. Для Docker при ошибке запуска предусмотрена попытка отката к прежнему образу.
10. Для системной службы сохраняет её прежнее состояние. Для контейнера сохраняет его Compose-параметры.

**Важно:** включение официального nginx.org может заменить пакеты Ubuntu/Debian пакетом nginx другого поставщика. Перед запуском на продуктивном сервере рекомендуется снять снапшот VPS. Скрипт проверяет некоторые опасные изменения, но не может гарантировать совместимость со всеми пользовательскими конфигурациями и сторонними модулями и не выполняет автоматический откат пакета при ошибке.

## Если одновременно работают два nginx: CDN и Docker Selfsteal

Например, литовская нода с **системным nginx.service** на IP CDN `88.216.62.216:443` и **Docker `nginx-selfsteal`** на другом IP `88.216.127.18:80`, где TCP 443 занят `rw-core`.

При одновременной работе обеих реализаций обычный `sudo sh nginx-updater.sh` (то же, что `--auto`) **откажется выбирать один из двух**. Это защита от случайного обновления неправильного nginx, а не ошибка установки.

Для обновления по отдельности:

~~~sh
# Сначала Docker Selfsteal — только контейнер и его Compose-файл:
sudo sh nginx-updater.sh --docker-update nginx-selfsteal

# Затем системный CDN nginx — только APT nginx, с сохранением ветки:
sudo sh nginx-updater.sh --system-update
~~~

Выполняйте команды **последовательно** и проверяйте CDN/сайт и работу VPN после каждой. При обновлении системного nginx скрипт разрешает наличие Docker-nginx **только если nginx.service реально активен**, а остальные процессы nginx принадлежат systemd или контейнерам. Для неиспользуемого (inactive) системного nginx при работающем Docker обновление будет заблокировано. При новой установке (`--install`) защита от дублирования nginx и конфликтов портов сохраняется.

Перед обновлением CDN рекомендуется проверить:

~~~sh
nginx -v
nginx -t
systemctl is-active nginx
sudo sh nginx-updater.sh --status
~~~

Учти: переход с дистрибутивного nginx на пакет nginx.org может менять пакетный состав. Скрипт резервирует конфигурацию и проверяет модули, но не гарантирует совместимость всех конфигураций. На ответственной CDN-ноде дополнительно полезен снапшот VPS.

## Если nginx работает в Docker

Например, для сервера с `rw-core` на TCP 443 и `nginx-selfsteal` на TCP 80, запущенным через Docker (`nginx:1.29.3-alpine`):

- `sudo sh nginx-updater.sh --status` покажет APT-пакет, процессы nginx, Docker-контейнеры и занятые порты;
- `sudo sh nginx-updater.sh --docker-status` покажет контейнерный образ, версию nginx и метки Docker Compose;
- `sudo sh nginx-updater.sh --auto` обновит именно рабочий Docker-nginx, не трогая неактивный системный nginx;
- `--install` тоже откажется создавать второй системный nginx при занятых портах или работающем nginx-контейнере.

APT не обновляет Docker-контейнеры. Поэтому `--auto` выбирает Docker при обнаружении одного рабочего nginx-контейнера; `--docker-update` позволяет явно указать контейнер и при необходимости версию.

### Обновление Docker-nginx одной командой

Для контейнера `nginx-selfsteal` в Нью-Йорке:

~~~sh
sudo sh nginx-updater.sh --docker-update nginx-selfsteal
~~~

Скрипт скачает официальный `nginx:stable-alpine`, определит реальную версию, закрепит в Compose конкретный тег (например, `nginx:1.30.7-alpine`), создаст резервную копию и проверит `nginx -t` в одноразовом контейнере. Лишь после успешной проверки он пересоздаст один выбранный сервис через `docker compose up -d --no-deps --force-recreate`. Если запуск или проверка нового контейнера не удастся, скрипт попробует автоматически вернуть старый Compose-файл и образ.

Для определённой версии:

~~~sh
sudo sh nginx-updater.sh --docker-update nginx-selfsteal nginx:1.30.7-alpine
~~~

**Ограничения:** поддерживается только запущенный контейнер с официальным образом `nginx:X.Y.Z-alpine` и одним обычным Compose-файлом, в котором образ указан одной простой строкой `image: nginx:X.Y.Z-alpine`. Для Compose с несколькими файлами, переменными подстановки, кастомными образами или неоднозначным YAML скрипт отменит действие. Монтирования за пределами каталога проекта не резервируются. Автоматический откат не гарантирован, поэтому для важных нод рекомендуются снапшоты.

**На New York**, где Docker-nginx был обновлён до 1.30.7, обычный запуск `sudo sh nginx-updater.sh` выберет Docker. Если новой stable-версии нет, контейнер не будет пересоздан.

Резервные копии Docker-проектов находятся в `/var/backups/nginx-updater/docker/ИМЯ_КОНТЕЙНЕРА/`.

**Пример диагностики:**

~~~sh
sudo sh nginx-updater.sh --status
sudo sh nginx-updater.sh --docker-status
docker inspect nginx-selfsteal --format '{{.Config.Image}}'
docker inspect nginx-selfsteal --format '{{index .Config.Labels "com.docker.compose.service"}}'
~~~

При новом развёртывании системного nginx (и только когда нет другого nginx и порты свободны):

~~~sh
sudo sh nginx-updater.sh --install
# После ручной настройки конфигурации:
sudo nginx -t && sudo systemctl enable --now nginx
~~~

## Поддержка

- Ubuntu 22.04 (jammy), 24.04 (noble), 26.04 (resolute)
- Debian 12 (bookworm), 13 (trixie)
- Архитектуры amd64 и arm64
- Официальные ветки nginx.org stable и mainline

Сторонние Docker-образы, NGINX Plus и nginx, собранный из исходников, автоматически не обновляются. Стандартный Docker Compose с официальным образом nginx Alpine поддерживается отдельной командой и через --auto, если это единственный работающий nginx.

## Обновление в дальнейшем через APT

Если официальный репозиторий nginx.org подключён, то обычная команда:

~~~sh
sudo apt update && sudo apt upgrade -y
~~~

также обновит nginx, если в подключённой ветке доступна более новая версия. Но она обновляет **не только nginx**, а и другие пакеты системы.

Для изолированного обновления nginx:

~~~sh
sudo apt update && sudo apt install --only-upgrade nginx
~~~

Или повторно запустите nginx_updater: он сам определит рабочий nginx (APT либо Docker):

~~~sh
sudo sh nginx-updater.sh --auto
~~~

## После обновления

Проверьте сайты с реальным доменным именем и корректным SNI, например:

~~~sh
curl -I --resolve example.com:443:127.0.0.1 https://example.com/
~~~

Сделайте внешнюю проверку VPN/прокси. Отсутствие ошибок nginx -t и запущенная служба не гарантируют доступности извне.

Если после обновления появилась ошибка:

~~~sh
sudo nginx -t
sudo journalctl -u nginx -n 100 --no-pager
ls -lht /var/backups/nginx-updater/
~~~

При необходимости используйте резервную копию для ручного восстановления конфигурации. Не заменяйте файлы наугад, если ошибка вызвана несовместимостью модулей, а не содержимым конфигурации.
