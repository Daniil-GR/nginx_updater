# nginx_updater

Управляемое обновление nginx через APT и Docker Compose. Скрипт подключает официальный репозиторий nginx.org, проверяет его ключ подписи, делает резервную копию конфигурации и устанавливает актуальный nginx. Интерфейс и сообщения на русском.

## Быстрый запуск

На сервере с Ubuntu или Debian:

~~~sh
curl -fL --retry 3 -o nginx-updater.sh \
  https://raw.githubusercontent.com/Daniil-GR/nginx_updater/main/nginx-updater.sh
sh -n nginx-updater.sh
sudo sh nginx-updater.sh
~~~

По умолчанию скрипт **обновляет только уже установленный системный nginx (APT)**. Он сохраняет подключённую ветку nginx.org (stable/mainline) или выбирает stable, если официальный репозиторий ещё не настроен. Если nginx работает в Docker, скрипт предупреждает об этом и прекращает APT-операции.

Для интерактивного меню:

~~~sh
sudo sh nginx-updater.sh --menu
~~~

## Команды

| Команда | Назначение |
| --- | --- |
| --auto | Обновить уже установленный системный nginx (по умолчанию) |
| --stable | Обновить или установить nginx stable |
| --mainline | Обновить системный nginx до mainline |
| --install | Впервые установить системный nginx stable (без автозапуска) |
| --docker-status | Посмотреть контейнеры nginx, версии образов и метки Compose |
| --docker-update NAME [IMAGE] | Обновить конкретный nginx-контейнер Compose до последней `stable-alpine` или до заданного `nginx:X.Y.Z-alpine` |
| --menu | Консольное меню управления |
| --status | Посмотреть версию, источник APT, статус nginx |
| --check | Обновить APT-индексы, посмотреть доступные версии |
| --test | Запустить nginx -t и показать загруженные конфиги |
| --diagnose | Посмотреть HTTP/2, динамические модули и слушающие порты |
| --backup | Сделать резервную копию nginx |
| --help | Помощь |

## Что делает автоматическое обновление

1. Проверяет ОС, наличие системного nginx и **работающие nginx-процессы**, включая Docker/контейнеры. Если системный nginx отсутствует или обнаружен другой экземпляр nginx, обычный `--auto` прекращает выполнение без установки пакета.
2. Проверяет текущую конфигурацию nginx (nginx -t).
3. При переходе с пакетов дистрибутива проверяет наличие динамических модулей, требующих ручной проверки совместимости. При отдельной новой установке (`--install`) дополнительно проверяет занятость портов 80/443.
4. Создаёт резервную копию /etc/nginx и информации о пакетах в /var/backups/nginx-updater/.
5. Настраивает nginx.org с проверкой официального GPG-ключа и отпечатка.
6. Сравнивает установленную версию с предлагаемой, запрещает автоматическое понижение версии.
7. Запускает симуляцию APT и прерывает установку, если требуется удалить пакеты, отличные от nginx-common.
8. Устанавливает только пакет nginx и необходимые зависимости с сохранением локальных конфигурационных файлов.
9. Снова проверяет nginx -t и удостоверяется, что число подключённых конфигураций sites-enabled не сократилось.
10. Если системный nginx был активен до обновления, перезапускает его и проверяет, что служба работает. При новой установке отключает автозапуск службы, чтобы она не занимала порты неожиданно.

**Важно:** включение официального nginx.org может заменить пакеты Ubuntu/Debian пакетом nginx другого поставщика. Перед запуском на продуктивном сервере рекомендуется снять снапшот VPS. Скрипт проверяет некоторые опасные изменения, но не может гарантировать совместимость со всеми пользовательскими конфигурациями и сторонними модулями и не выполняет автоматический откат пакета при ошибке.

## Если nginx работает в Docker

Например, для сервера с `rw-core` на TCP 443 и `nginx-selfsteal` на TCP 80, запущенным через Docker (`nginx:1.29.3-alpine`):

- `sudo sh nginx-updater.sh --status` покажет APT-пакет, процессы nginx, Docker-контейнеры и занятые порты;
- `sudo sh nginx-updater.sh --docker-status` покажет контейнерный образ, версию nginx и метки Docker Compose;
- `sudo sh nginx-updater.sh --auto` **не будет** обновлять хостовый nginx, потому что это не обновит рабочий nginx в Docker;
- `--install` тоже откажется создавать второй системный nginx при занятых портах или работающем nginx-контейнере.

APT не обновляет Docker-контейнеры. Для них добавлен **отдельный явный режим** `--docker-update`: он изменяет Compose и пересоздаёт только выбранный сервис, а `--auto` продолжает управлять только APT. Режим Docker не включается автоматически при запуске без аргументов.

### Обновление Docker-nginx одной командой

Для контейнера `nginx-selfsteal` в Нью-Йорке:

~~~sh
sudo sh nginx-updater.sh --docker-update nginx-selfsteal
~~~

Скрипт скачает официальный `nginx:stable-alpine`, определит реальную версию, закрепит в Compose конкретный тег (например, `nginx:1.30.7-alpine`), создаст резервную копию и проверит `nginx -t` в одноразовом контейнере. Лишь после успешной проверки он пересоздаст один выбранный сервис через `docker compose up -d --no-deps --force-recreate`. Если запуск или проверка нового контейнера не удастся, скрипт попробует автоматически вернуть старый Compose-файл и образ.

Для определённой версии:

~~~sh
sudo sh nginx-updater.sh --docker-update nginx-selfsteal nginx:1.30.7-alpine
~~~

**Ограничения:** поддерживается только запущенный контейнер с официальным образом `nginx:X.Y.Z-alpine` и одним обычным Compose-файлом, в котором образ указан одной простой строкой `image: nginx:X.Y.Z-alpine`. Для Compose с несколькими файлами, переменными подстановки, кастомными образами или неоднозначным YAML скрипт отменит действие. Монтирования за пределами каталога проекта не резервируются. Автоматический откат не гарантирован, поэтому для важных нод рекомендуются снапшоты.

**На New York после обновления 1.30.7** повторный запуск проверит актуальность версии и не пересоздаст контейнер без изменения образа.

Резервные копии Docker-проектов находятся в `/var/backups/nginx-updater/docker/ИМЯ_КОНТЕЙНЕРА/`.

**Пример диагностики:**

~~~sh
sudo sh nginx-updater.sh --status
sudo sh nginx-updater.sh --docker-status
docker inspect nginx-selfsteal --format '{{.Config.Image}}'
docker inspect nginx-selfsteal --format '{{index .Config.Labels "com.docker.compose.service"}}'
~~~

При новом развёртывании системного nginx (и только когда нет другого nginx и порты свободны):

~~~sh
sudo sh nginx-updater.sh --install
# После ручной настройки конфигурации:
sudo nginx -t && sudo systemctl enable --now nginx
~~~

## Поддержка

- Ubuntu 22.04 (jammy), 24.04 (noble), 26.04 (resolute)
- Debian 12 (bookworm), 13 (trixie)
- Архитектуры amd64 и arm64
- Официальные ветки nginx.org stable и mainline

Сторонние Docker-образы, NGINX Plus и nginx, собранный из исходников, автоматически не обновляются. Стандартный Docker Compose с официальным образом nginx Alpine поддерживается в отдельном режиме.

## Обновление в дальнейшем через APT

Если официальный репозиторий nginx.org подключён, то обычная команда:

~~~sh
sudo apt update && sudo apt upgrade -y
~~~

также обновит nginx, если в подключённой ветке доступна более новая версия. Но она обновляет **не только nginx**, а и другие пакеты системы.

Для изолированного обновления nginx:

~~~sh
sudo apt update && sudo apt install --only-upgrade nginx
~~~

Или повторно запустите nginx_updater для **уже установленного системного nginx**:

~~~sh
sudo sh nginx-updater.sh --auto
~~~

## После обновления

Проверьте сайты с реальным доменным именем и корректным SNI, например:

~~~sh
curl -I --resolve example.com:443:127.0.0.1 https://example.com/
~~~

Сделайте внешнюю проверку VPN/прокси. Отсутствие ошибок nginx -t и запущенная служба не гарантируют доступности извне.

Если после обновления появилась ошибка:

~~~sh
sudo nginx -t
sudo journalctl -u nginx -n 100 --no-pager
ls -lht /var/backups/nginx-updater/
~~~

При необходимости используйте резервную копию для ручного восстановления конфигурации. Не заменяйте файлы наугад, если ошибка вызвана несовместимостью модулей, а не содержимым конфигурации.
